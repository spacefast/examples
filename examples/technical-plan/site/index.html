01

Problem

Field work fails where connectivity is weakest—and recovery is invisible.

What users experience

Northstar’s inspection teams work in basements, utility corridors, and rural facilities. Today, a dropped request looks like a saved task until the screen is refreshed. Supervisors discover missing notes hours later, after the technician has left the site.

Why now

Offline reliability is the top blocker in 18 of 31 enterprise evaluations this quarter. The mobile team also plans to replace its ad-hoc request cache in Q4; doing both as one designed system avoids a second migration.

02

Scope

The beta is deliberately narrow enough to observe and reverse.

In scope

  • Create and update tasks, inspection notes, and status changes offline
  • Cache the last 30 days of assigned project data per device
  • Show pending, synced, conflicted, and failed states on every mutation
  • Remote disable, queue diagnostics, and workspace-level rollout controls

Not in this release

  • Offline attachment uploads or media transcoding
  • Collaborative rich-text editing or peer-to-peer device sync
  • Full project export, billing changes, or account administration
  • Desktop web offline mode
Security
Encrypt queued payloads with a device-bound key and erase them on remote sign-out.
Compatibility
Support the current and previous two mobile releases during the beta.
Operations
No new stateful service in the critical path before general availability.

03

Architecture

Clients record intent locally; the existing API remains the source of truth.

Replay and ordering

A device replays one project queue at a time in creation order. Different projects may sync concurrently, capped at three to protect battery and API capacity.

Conflict policy

Status transitions use domain rules; scalar task fields use revision-aware last-write-wins; note bodies fork visibly when both sides changed.

Failure handling

Retry transient failures with jitter. Stop on authorization or validation errors, preserve the draft, and show the user a specific recovery action.

Observability

Record queue age, attempts, settle time, conflict class, and client version. Never include note text or customer payloads in telemetry.

06

Decisions

Recorded choices keep settled tradeoffs from reopening by accident.

  1. D-01 · Accepted

    Keep the server authoritative

    Choose queued commands over client-side replicated state. It fits current domain rules and operations skills; the cost is limited offline query flexibility. Revisit if desktop and mobile both require multi-day offline editing.

  2. D-02 · Accepted

    Use encrypted SQLite, not a custom log file

    Transactions, migrations, and bounded queries matter more than a smaller binary. Revisit only if measured storage overhead exceeds 15% on supported devices.

  3. D-03 · Accepted

    Fork conflicting notes instead of merging text

    A visible duplicate is safer than an invented merge for compliance records. Rich-text collaboration remains outside the beta.

  4. D-04 · Proposed

    Gate rollout by workspace

    Workspace controls align support, telemetry, and customer consent. Approval is requested in this review so the API contract can freeze in Phase 1.
